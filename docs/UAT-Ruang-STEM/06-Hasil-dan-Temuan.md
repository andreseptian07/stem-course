# Lembar hasil dan temuan pengujian Ruang STEM

Salin berkas ini untuk setiap putaran. Semua hasil awal **Belum diuji**; jangan memakai tanda centang sebagai bukti tanpa hasil aktual. Rincian langkah/harapan ada pada dokumen peran dan pengujian umum.

## Status hasil

- **Lulus:** langkah dijalankan dan hasil aktual sesuai.
- **Gagal:** langkah dijalankan tetapi hasil menyimpang; isi nomor temuan.
- **Terblokir:** tidak bisa dijalankan karena prasyarat, layanan, akses, waktu atau lingkungan belum tersedia. Tulis hambatan dan pemiliknya.
- **Belum diuji:** belum dijalankan.
- **Tidak berlaku:** koordinator menyatakan di luar lingkup putaran dan menulis alasannya; tidak dihitung Lulus.

Kasus yang terdiri dari beberapa percobaan dinilai Lulus setelah semua bagian yang masuk lingkup berhasil. Pisahkan subhasil bila kondisi nonaktif sudah diuji tetapi keberhasilan layanan aktif masih Terblokir. Kasus umum diulang pada peran berbeda; duplikasi baris jika diperlukan untuk Tutor B/Siswa B/C, browser lain atau pengujian ulang. Simpan hasil awal dan hasil ulang, jangan menghapus riwayat gagal.

## Format laporan bug atau usulan

Salin satu blok untuk satu temuan. Untuk beberapa gejala dengan penyebab belum jelas, pisahkan agar hasil reproduksi tidak tercampur.

```text
Nomor temuan: UAT-YYYYMMDD-001
ID kasus / sublangkah:
Tanggal dan waktu WIB:
Rilis / browser / perangkat:
Alias akun, status akun, kelas dan penugasan:
URL aman tanpa token:
Jenis: Bug / Tambah / Ubah / Kurangi
Prioritas: P0 / P1 / P2 / P3
Prasyarat dan data UAT:
Langkah reproduksi:
1.
2.
3.
Hasil yang diharapkan:
Hasil aktual:
Dampak / pengguna yang terdampak:
Bukti screenshot/video yang sudah disamarkan:
Frekuensi: selalu / kadang (berapa dari berapa percobaan)
Jalan alternatif, jika ada:
Penanggung jawab perbaikan:
Status: Baru / Ditinjau / Diperbaiki / Diuji ulang / Ditutup / Dijadwalkan
Rilis perbaikan:
Hasil pengujian ulang dan kasus terkait:
```

| Prioritas | Arti dan contoh |
| --- | --- |
| P0 | Data privat akun lain terbuka, hak Admin/Tutor diperoleh tanpa izin, atau kehilangan data penting. Hentikan jalur yang bermasalah dan laporkan segera; cukup bukti minimal pada objek UAT. |
| P1 | Login normal, belajar wajib, kirim/review tugas, penyimpanan berkas utama atau penerbitan yang sudah memenuhi syarat gagal tanpa jalan alternatif. Menghalangi pilot. |
| P2 | Fungsi pendukung/angka/navigasi salah atau membingungkan dengan alternatif yang layak. Tetap dicatat dan dinilai pemilik sebelum pilot. |
| P3 | Teks, warna atau jarak kurang baik tanpa menghalangi penyelesaian tugas. |

Prioritas ditentukan oleh dampak aktual, bukan sekadar ID kasus. Untuk usulan fitur, tulis tujuan pengguna, seberapa sering dibutuhkan dan apakah wajib untuk pilot. Jangan menamai SMTP/Judge0 nonaktif sebagai bug sukses pengiriman/penilaian; laporkan sebagai Terblokir sesuai konfigurasi, sementara pesan/perlindungan saat layanan mati tetap diuji.
